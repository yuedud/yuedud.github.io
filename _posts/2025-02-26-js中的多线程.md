## 一句话概览

如何在js中进行高效的数据传输和内容共享

## 引言

在现代 web 应用程序中，随着对性能和响应性的要求不断提高，利用多线程来处理复杂任务变得越来越重要。Web Worker 提供了一种在后台线程中运行 JavaScript 代码的机制，使得主线程可以保持流畅的用户体验。在 Web Worker 的使用过程中，数据传输的效率和安全性尤为关键。为此，JavaScript 提供了两种强大的工具：Transferable Objects 和 SharedArrayBuffer。
Transferable Objects 允许开发者高效地在主线程和 Worker 之间传递数据，通过转移对象的所有权而非复制数据，显著减少了内存开销和延迟。这种机制特别适合处理大型数据，如图像或音频缓冲区，确保在不同执行上下文间的数据传递既快速又有效。
另一方面，SharedArrayBuffer 使得多个线程能够共享同一块内存区域，配合 Atomics API，提供了原子操作的能力，确保数据的一致性和完整性。这种方式非常适合需要频繁读写和实时更新数据的应用场景，如实时数据处理等。

## 名词解释

**Web Worker**

Web Worker 是一种在浏览器中运行的 JavaScript 线程，用于处理计算密集型任务而不阻塞主线程。通过将复杂的计算分配给 Worker，开发者可以保持用户界面的响应性。Worker 运行在独立的线程中，无法直接访问 DOM，但可以通过消息传递与主线程进行通信。

**ArrayBuffer**

ArrayBuffer 是一种用于表示通用、固定长度的原始二进制数据缓冲区的对象。它通常与 typed arrays（如 Uint8Array）一起使用，用于处理大量的二进制数据。

**Transferable Objects**

Transferable Objects 是一种特殊的 JavaScript 对象，允许在不同的执行上下文之间高效地传递数据。使用 Transferable Objects 时，数据的所有权会从一个上下文转移到另一个上下文，而不是复制数据，从而提高性能。常见的可转移对象包括 ArrayBuffer 和 ImageBitmap。

**SharedArrayBuffer**

SharedArrayBuffer 是一种特殊的类型，用于在主线程和 Web Worker 之间共享内存。它允许多个线程同时访问同一段内存，适合需要高性能和低延迟的应用场景，如并行计算和实时数据处理。

## 通信

### 主线程发布消息到worker线程

```js
// main.js
const worker = new Worker('worker.js');
worker.postMessage('Hello, Worker!');
 
// worker.js
self.onmessage = function(event) {
    console.log('Message from Main Thread:', event.data);
};
```

### worker线程发布消息到主线程

```js
// main.js
const worker = new Worker('worker.js');
worker.onmessage = function(event) {
    console.log('Message from Worker:', event.data);
};
 
// worker.js
self.postMessage('Hello, Main Thread!');
```

## 通信方式

**StructuredClone 内存复制**

主线程和worker传递数据默认采用内存复制的方式来实现，即结构化克隆算法，简单可以理解为深拷贝。
结构化克隆算法是一种用于在 Web 环境中复制对象的算法

<https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Workers_API/Structured_clone_algorithm>

**Transferable Objects 内存转移**

在主线程和worker之间还可以通过内存转移的方式进行通信，使用 Transferable Objects 时，数据不会被复制，而是直接转移其内存所有权。原始对象在发送后会被“剥离”，主线程无法再访问。

<https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Workers_API/Transferable_objects>

**Shared Array Buffer 内存共享**

在主线程和worker线程之间还可以通过内存共享的方式来共享数据。SharedArrayBuffer它允许多个线程同时访问同一段内存，适合需要高性能和低延迟的应用场景，如并行计算和实时数据处理。

<https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer>

## StructuredClone 内存复制

在线程之间通信默认是用结构化克隆算法进行复制通信
即 主线程将Object A通过postMessage通信给worker线程后，主线程仍持有Object A的所有权，且worker线程也持有Object A Copy的所有权，两份数据完全独立。
window上提供了结构化克隆算法的能力 structuredClone

### 使用

使用 postMessage 方法发送 Transferable Objects 非常简单。我们可以指定一个数组作为第二个参数，包含要转移的对象。

```js
window.postMessage(message, [transfer]);
```

一旦传输完成，主线程中的 buffer 将不再可用，所有的引用都指向 Worker 中的新内存地址。

### 原子性和安全性

Transferable Objects 的转移过程是原子的，确保在传输过程中不会出现中间状态。这种设计避免了数据竞争的问题，从而增强了数据的一致性和安全性。

## Shared Array Buffer 共享内存

SharedArrayBuffer 是一种用于在不同执行上下文（如主线程和 Web Worker）之间共享内存的对象。与传统的 ArrayBuffer 不同，SharedArrayBuffer 允许多个线程同时读取和修改内存中的数据，而不需要数据的复制和转移。

### Atomics 安全性

Atomics 是 JavaScript 中的一个全局对象，提供了一组静态方法，用于在 Web Worker 或其他多线程环境中进行原子操作。原子操作是指在并发编程中，某个操作要么完全执行，要么完全不执行，避免了数据竞争和不一致性的问题。

<https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Atomics>

```js
Atomics.add()
Atomics.sub()
Atomics.and()
Atomics.or()
Atomics.xor()
Atomics.compareExchange()
Atomics.exchange()
Atomics.load()
Atomics.store()
Atomics.wait()
Atomics.notify()
```

### 原子操作

当内存被共享时，多个的线程能够读写内存上的同一数据。原子操作会确保正在读或写的数据的值是符合预期的，即下一个原子操作一定会在上一个原子操作结束后才会开始，其操作不会被中断。

### 等待和通知

wait() 和 notify() 可以让进程一直等待直到某个特定的条件为真，主要用于实现阻塞。
